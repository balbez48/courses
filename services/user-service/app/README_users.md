# Модуль управления пользователями

## Назначение

Модуль реализует работу с пользователями системы курсов повышения квалификации: модель пользователя, проверку данных, CRUD-доступ к таблице PostgreSQL `listeners` и обработку событий через паттерны «Декоратор» и «Наблюдатель».

## Что реализовано

| Компонент | Назначение | Результат |
|---|---|---|
| `User` | Хранит ID, имя, email и роль | Объект пользователя |
| `BuilderUser` | Собирает пользователя и проверяет имя, email и роль | `build()` возвращает `User`, ошибки — `ValueError` |
| `UserStorage` | Общий интерфейс хранилища | Контракт шести методов |
| `UserRepository` | CRUD-операции с таблицей `listeners` | Результаты SQL-операций |
| `ObservedUserRepository` | Уведомляет наблюдателей после успешных изменений | Возвращает результат внутреннего хранилища |
| `AuditLogObserver` | Формирует запись аудита | Добавляет словарь в `logs` |
| `EmailNotificationObserver` | Готовит письма при создании пользователя и смене роли | Добавляет словарь в `sent_emails` |
| `NewUserBroadcastObserver` | Готовит уведомление для остальных пользователей при регистрации | Добавляет словари в `messages` |

## Методы хранилища

- `insert(user, admin_id=None)` — добавляет пользователя, возвращает созданного `User`. При занятом email выбрасывает `DuplicateEmailError`.
- `update(user, admin_id=None)` — обновляет запись по `user.user_id`, возвращает `User` или `None`, если ID не найден. Дубликат email вызывает `DuplicateEmailError`.
- `delete(user_id, admin_id=None)` — удаляет запись, возвращает `True`, если строка удалена, иначе `False`.
- `get_all()` — возвращает список пользователей в порядке ID.
- `get_by_id(user_id)` — возвращает пользователя или `None`.
- `get_by_email(email)` — ищет по email без учёта регистра и пробелов по краям.

`admin_id` — ID администратора, выполнившего операцию. Сам `UserRepository` его не использует; параметр нужен декоратору и наблюдателям.

## Как работает декоратор

1. Изменяющая операция сначала выполняется во внутреннем хранилище.
2. После успешной операции декоратор вызывает `on_user_changed` у каждого наблюдателя.
3. При обновлении сравниваются старая и новая роли: если роль изменилась, передаётся `UPDATE_ROLE`, иначе — `UPDATE`.
4. При чтении (`get_all`, `get_by_id`, `get_by_email`) наблюдатели не вызываются.
5. Ошибка одного наблюдателя записывается в лог Python и не отменяет уже выполненную операцию с БД.
6. `threading.Lock` не позволяет нескольким потокам одновременно выполнять цикл уведомления у одного экземпляра декоратора.

## События

| Событие | Условие |
|---|---|
| `INSERT` | Пользователь успешно добавлен |
| `UPDATE` | Пользователь обновлён, роль не изменилась |
| `UPDATE_ROLE` | Пользователь обновлён, роль изменилась |
| `DELETE` | Пользователь успешно удалён |

## Наблюдатели

- `AuditLogObserver` добавляет в `logs` словарь с ID события, ID администратора, действием, ID пользователя и временем.
- `EmailNotificationObserver` добавляет в `sent_emails` шаблон письма при `INSERT` и `UPDATE_ROLE`.
- `NewUserBroadcastObserver` при `INSERT` вызывает переданную функцию `get_all_emails` и добавляет уведомление всем адресам, кроме email нового пользователя.

## Ограничения текущей реализации

Это фактическое состояние переданных файлов.

1. **Аудит хранится только в памяти.** `AuditLogObserver` заполняет `self.logs`, но не записывает данные в PostgreSQL `audit_logs`. После перезапуска процесса список теряется.
2. **Почта фактически не отправляется.** `EmailNotificationObserver` только формирует словари в `sent_emails`. SMTP или HTTP-интеграции нет.
3. **Массовая рассылка фактически не отправляется.** `NewUserBroadcastObserver` только формирует словари в `messages`.
4. **Проверка email базовая.** Регулярное выражение проверяет общий формат, но не существование почтового ящика.
5. **Builder проверяет имя, email и роль.** Уникальность email дополнительно обеспечивает ограничение БД; существование пользователя и корректность `user_id` Builder не проверяет.
6. **Событие `UPDATE` тоже передаётся наблюдателям.** Текущие email- и broadcast-наблюдатели его игнорируют, но другие реализации могут обработать.

## Пример подключения

```python
repository = UserRepository()
audit = AuditLogObserver()
email = EmailNotificationObserver()
broadcast = NewUserBroadcastObserver(
    lambda: [user.email for user in repository.get_all()]
)

observed_repository = ObservedUserRepository(
    repository,
    [audit, email, broadcast]
)

# Операции с пользователями выполняются через observed_repository.
# Например: created = observed_repository.insert(user, admin_id=1)
```

Нужны импорты классов и настроенное подключение `Database`.

## Что не входит в переданный модуль

Проектное решение описывает систему целиком, но загруженные Python-файлы реализуют только часть управления пользователями. В них нет реализации:

- управления курсами и уроками;
- записи на курсы и проверки свободных мест;
- статусов обучения и прогресса по урокам;
- генерации и проверки сертификатов;
- разграничения доступа по ролям на уровне приложения;
- реальной отправки email и массовых уведомлений;
- сохранения аудита в таблицу `audit_logs`.

Наличие этих требований в проектном решении не означает, что они реализованы в данном модуле.

## Подключение к PostgreSQL (`Database`)

Класс `Database` реализует управление подключениями к PostgreSQL и используется репозиторием через `Database().cursor()`.

- `Database()` — возвращает единственный экземпляр класса (Singleton). При первом обращении создаёт пул соединений.
- `__new__()` — создаёт `ThreadedConnectionPool` с минимальным количеством 1 и максимальным количеством 10 соединений. Параметры подключения берутся из переменных окружения `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`; если они не заданы, используются значения по умолчанию из кода.
- `cursor()` — контекстный менеджер. Выдаёт курсор, после успешного выполнения делает `commit()`, при исключении — `rollback()`, затем возвращает соединение в пул. Возвращаемое значение внутри блока `with` — курсор PostgreSQL.
- `close()` — закрывает все соединения пула и сбрасывает Singleton, чтобы при следующем обращении пул мог быть создан заново.

Использование:

```python
with Database().cursor() as cursor:
    cursor.execute("SELECT * FROM listeners")
    rows = cursor.fetchall()
```

`UserRepository` не создаёт отдельное подключение для каждой операции: он получает курсор через этот общий класс. `ThreadedConnectionPool` позволяет использовать пул в многопоточной программе.

**Примечание по настройке:** значения подключения по умолчанию подходят только для локальной разработки. Для другого окружения следует задать переменные `DB_*`.
